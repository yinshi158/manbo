# 曼波 Manbo

> 输入的不只是文字。

曼波（Manbo）是一个使用 **Rust** 开发的跨平台输入法。

> 演示动图待补（原演示媒体的版权与品牌属于上游，已移除）。

整句拼音一口气敲完，停顿一下由本地小模型重排候选，候选旁附英文译文与词性。

它的目标不只是「把拼音转换成中文」，而是让输入本身成为一种轻量、持续、几乎没有额外负担的语言学习方式。

当你输入文字时，曼波会在候选词旁边显示一条简洁的目标语言译文。

例如，当你的主要语言是中文、正在学习英语时：

```text
1  开发            development
2  编程            programming
3  架构            architecture
4  编译            compile
5  语言            language
```

候选词仍然是输入的主体，翻译只作为较小、较浅的辅助信息存在。

**一次只学习一种语言。** 曼波不会在一个候选项旁边同时塞入英语、日语、韩语、德语。保持输入体验干净，比堆砌信息更重要。

## 原项目

**青简（Qingjian）** 是用 Rust 写的跨平台中文输入法：核心引擎与平台无关，macOS 走 Input Method Kit，Windows 走 TSF（文本服务 DLL + 独立的引擎进程）。
整句拼音一次上屏、候选旁带译文与词性（打字顺手认词）、本地学习越用越顺、可选的云联想。本仓库是它的改名分支。

- 上游仓库：<https://github.com/qingjian-team/qingjian>

## 相对原项目改了什么

**① 新增：多设备学习数据同步**（上游没有这个功能）

- 合并的是「调教」的成果：用户词、词频、个人 n-gram、选词记录、敲错表、个人英文词、按天打字统计、个人释义表与配置文件；输入日志、密钥、导入的词库与模型永不上传。
- 后端两种：WebDAV（坚果云 / Nextcloud / NAS）或一个本地同步文件夹（交给 iCloud Drive / Dropbox / Syncthing 传）。
- 不是整文件覆盖，而是逐键三方合并 `merged = 远端 + (本地 − 基准)`：两台各自攒的记录相加、删除与「忘掉」会传过去、重复同步不重复计数；基准快照放在 `<数据目录>/sync/base/`。
- 时机：启动与退出各一轮、运行中每 15 分钟一轮（可改）；Windows 在「设置 → 同步」里配置并「立即同步」，macOS 走配置文件的 `[sync]` 分节（输入法菜单里也有「立即同步」）。
- 设计与取舍：[docs/design/sync.md](docs/design/sync.md)。

**② 修好 Windows 10 上设置程序起不来**

- 设置程序改成自包含部署（exe 旁边自带 Windows App Runtime），并把只有 Windows 11 才有的两个 AppModel API 改成延迟加载，不再依赖机器上装没装框架包——否则 Windows 10 在**加载期**就报「无法定位程序输入点 TryCreatePackageDependency」。
- 打包脚本读运行时清单时补了 `-Encoding UTF8`：清单里有中文注释，Windows PowerShell 5.1 缺省按 ANSI(GBK) 解码会吃掉换行、把紧跟注释的那条文件当成注释丢掉，打出的包装到 Windows 10 上设置程序会缺 DLL、启动即退出。
- 定位与验证过程：[docs/notes/windows-win10.md](docs/notes/windows-win10.md)。

**③ 品牌与标识改名**（「青简」→「曼波 Manbo」）

- 名字与自绘图标；crate 与产物名（`manbo-*`、`manbo-server.exe`、`manbo-settings.exe`、`manbo_tsf.dll`）、命名管道（`\\.\pipe\manbo`）、安装目录（`Program Files\Manbo`）、数据目录（`%APPDATA%\Manbo`）、macOS bundle id（`app.manbo.inputmethod`）。
- 安装包的 AppId 换成新 GUID：与上游版本**可以并存安装**，不会互相覆盖。
- `.qj` 数据容器写入新魔数 `MANBO\0\0\0`、读取兼容上游的 `QINGJIAN`——否则已有的词库 / 语言模型 / 释义表 / 整句模型会全部读不出来。

**没有改的**：除以上三项，功能与实现与上游一致。本改版自己的仓库地址与反馈渠道：（待维护者填写）

## 核心理念

> 学习语言为什么一定要专门打开一个学习软件？

聊天、写代码、搜索、记笔记、写文档、发邮件……大量时间其实都花在输入文字上。

如果这些每天发生数百次的输入行为，本身就能顺便提供一点语言反馈，语言学习就可以从「专门腾时间学习」变成日常行为的一部分。

**输入的时候，顺便多认识一个词。**

不打断。不弹题。不强迫记忆。只是悄悄地把翻译放在那里。

## 语言模式

用户可以设置：

```text
Primary Language: 中文
Learning Language: English
```

切换学习语言为日语后，同样的候选会显示：

```text
开发                開発
学习                学習
语言                言語
```

未来支持其他输入模式后，也可以反过来：

```text
こんにちは          你好
日本語              日语
```

核心原则不变：**一个候选词，只显示一种辅助语言。**

## 平台

曼波从一开始就按跨平台架构设计：核心输入引擎平台无关，各平台只负责接入系统输入接口与候选窗口。

```text
macOS    → Input Method Kit (IMK)
Windows  → Text Services Framework (TSF)
Linux    → IBus / Fcitx
```

开发顺序是 macOS 优先；Windows 版已进入内测（TSF 文本服务 + 独立的输入引擎进程）。

---

## 不打算做什么

曼波暂时不准备成为一个「大而全」的语言学习软件。它不会：

- 在候选框塞入五六种语言
- 每输入几个词就弹出测试
- 强制用户背单词
- 用复杂 UI 干扰正常输入
- 为了学习功能牺牲输入效率

输入法首先必须是一个好用的输入法。语言学习建立在这个前提之上。

如果用户需要思考「我现在到底是在打字还是在背单词」，那曼波大概就设计错了。

## 隐私

**曼波不上传任何数据。** 拼音转换、词库、学习、释义全部在本机完成，没有账号，没有统计上报。
云联想（缺省关闭）打开后，请求直接从你的电脑发到你自己填写的 AI 服务商，不经过作者；输入日志只写在本机，可以随时关闭和清空。
细节见文档 [数据与日志](docs/user/help/data-and-logs.md)。
